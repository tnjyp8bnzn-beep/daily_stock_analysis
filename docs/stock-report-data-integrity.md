# 股票报告数据与结论校验

本次修复不修改股票列表、模型配置、Actions 定时任务或 Secrets，不增加服务或收费 API。

- TickFlow 按代码查询行情时，每批最多 5 只。6 只会分为 5+1；更小的自定义批量仍生效。去重不改变顺序。批次失败不阻止后续批次，未缓存的股票继续走原有逐股获取和数据源降级流程。上游全源失败仍会明确失败，分批不保证上游永远可用。
- 原始日线快照与实时技术指标覆盖分开保存。日线交易日、来源和最新报价分别展示；只有日期及交易阶段支持完整日线时才使用“收盘”标签，实时覆盖始终标为估算价。最新报价不自动认定为收盘价。
- 报告和模型输入显示供应商报价时间、实际获取时间，以及两者的秒数差；时间统一为含时区的 ISO 8601。没有供应商时间、没有时区、时间格式异常或报价时间晚于获取时间时，不生成虚假的零延迟。无法确认的字段显示“无法确认 / 数据缺失”。此延迟是报价至获取的时间差，盘后也包含休市时间，并非单纯网络延迟。
- TickFlow 缓存命中保留最初获取时间，不以读取缓存的时间代替。历史日线表未保存精确的供应商报价/获取时间时，明确显示缺失，不把交易日午夜、数据库写入时间或报告生成时间冒充这两个时间。
- 模型输入明确禁止编造实时新闻、资金流向、市场情绪和机构观点。最终报告校验会移除缺少输入证据的事实表述；新闻等事实采用输入中带日期、链接的原文摘录。模型生成的链接或“未找到信息”占位文本不构成证据。价格和成交量不构成主力资金或机构行为的直接证据。结构化资金数据可按真实来源和值展示。
- 价格、均线或操作理由缺失，以及 JSON 解析失败时，只能观望；结论、显式动作、持仓建议、即时行动或建仓计划发生方向冲突时统一降级观望，清除入场点并同步计划。观望/持有不展示新建仓指令。保留原始模型评分，但写入护栏原因，防止展示层和决策信号按分数重新升级为买入/卖出。
- 常规分析、直接 analyzer 调用和 Agent 的最终保存路径都执行校验。大盘复盘的独立模型输出路径也使用同一事实摘录规则，先校验模型文字，再注入实际获取的结构化表格。Agent 工具期的新闻若未以可核查原文进入最终校验上下文，则保守显示缺失；不因搜索计数大于零就信任模型文字。
- PushPlus 使用 HTTPS，同时检查 HTTP 状态和业务 `code`。HTTP 200 不代表业务成功；实名认证错误会明确提示登录官网完成认证，返回失败。`code=200` 仅表示平台受理，最终送达以平台记录为准。分段推送任一段失败，整体返回失败。日志对已配置 Token 脱敏。

分析任务成功与通知成功是独立状态。Actions 的绿色结果表示分析任务完成，不代表 PushPlus 最终送达；通知服务对全部失败返回 `all_failed`，多渠道部分失败保留逐渠道结果。未改变现有调度和退出码约定。

变更不会重写已经生成的报告。合入后应由有权限的维护者检查下一次 Actions 的逐股结果和通知日志；不应为了验证而新增收费 API 或公开 Secrets。
