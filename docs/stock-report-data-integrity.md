# 股票报告数据与结论校验

本次修复不修改股票列表、模型配置、Actions 定时任务或 Secrets，不增加服务或收费 API。

- TickFlow 按代码查询行情时，每批最多 5 只。6 只会分为 5+1；更小的自定义批量仍生效。去重不改变顺序。批次失败不阻止后续批次，未缓存的股票继续走原有逐股获取和数据源降级流程。上游全源失败仍会明确失败，分批不保证上游永远可用。
- 原始日线快照与实时技术指标覆盖分开保存。日线交易日、来源和最新报价分别展示；只有日期及交易阶段支持完整日线时才使用“收盘”标签，实时覆盖始终标为估算价。最新报价不自动认定为收盘价。
- 报告和模型输入显示供应商报价时间、实际获取时间，以及两者的秒数差；时间统一为含时区的 ISO 8601。没有供应商时间、没有时区、时间格式异常或报价时间晚于获取时间时，不生成虚假的零延迟。无法确认的字段显示“无法确认 / 数据缺失”。此延迟是报价至获取的时间差，盘后也包含休市时间，并非单纯网络延迟。
- TickFlow 缓存命中保留最初获取时间，不以读取缓存的时间代替。历史日线表未保存精确的供应商报价/获取时间时，明确显示缺失，不把交易日午夜、数据库写入时间或报告生成时间冒充这两个时间。
- 模型输入明确禁止编造实时新闻、资金流向、市场情绪和机构观点。最终报告校验会移除缺少输入证据的事实表述；新闻等事实采用输入中带日期、链接的原文摘录。模型生成的链接或“未找到信息”占位文本不构成证据。价格和成交量不构成主力资金或机构行为的直接证据。结构化资金数据可按真实来源和值展示。
- 价格、均线或操作理由缺失，以及 JSON 解析失败时，只能观望；结论、显式动作、持仓建议、即时行动或建仓计划发生方向冲突时统一降级观望，清除入场点并同步计划。观望/持有不展示新建仓指令。保留原始模型评分，但写入护栏原因，防止展示层和决策信号按分数重新升级为买入/卖出。
- 常规分析、直接 analyzer 调用和 Agent 的最终保存路径都执行校验。大盘复盘的独立模型输出路径也使用同一事实摘录规则，先校验模型文字，再注入实际获取的结构化表格。Agent 工具期的新闻若未以可核查原文进入最终校验上下文，则保守显示缺失；不因搜索计数大于零就信任模型文字。
- Agent 的最终动作解释在全部报告护栏之后生成，`report_consistency` 作为新增调整来源记录动作变化；历史风控/专家信号保留原有枚举，不改成操作文案。报告、dashboard、存档与决策信号使用同一最终动作。观望会清除入场指令，但保留已有止损、条件风控及无关展示字段；止损无法确定时保留字段并明确标注数据缺失，不编造价格。旧结果缺少可选 `decision_type` 时按保守动作补齐，不中断存档。
- PushPlus 使用 HTTPS，同时检查 HTTP 状态和业务 `code`。HTTP 200 不代表业务成功；实名认证错误会明确提示登录官网完成认证，返回失败。`code=200` 仅表示平台受理，最终送达以平台记录为准。分段推送任一段失败，整体返回失败。日志对已配置 Token 脱敏。

分析任务成功与通知成功是独立状态。Actions 的绿色结果表示分析任务完成，不代表 PushPlus 最终送达；通知服务对全部失败返回 `all_failed`，多渠道部分失败保留逐渠道结果。未改变现有调度和退出码约定。

变更不会重写已经生成的报告。合入后应由有权限的维护者检查下一次 Actions 的逐股结果和通知日志；不应为了验证而新增收费 API 或公开 Secrets。

## 成交量、时段和风控数据契约

国内证券标准数据统一为成交量 **股**、成交额 **元**、涨跌幅 **百分数**（0.40 表示 0.40%）。仅在数据源适配入口转换；数据库、实时叠加、量能比较和报告不再重复换算。报告将股数展示为股/万股/亿股，将金额展示为元/万元/亿元。

| 路径 | 原始单位及处理 |
|---|---|
| Efinance A 股/ETF 日线、股票/ETF 实时及东财指数实时 | 成交量手 → ×100 股；成交额元保持不变。缺失 OHLC/量额不填成平价/0。 |
| TickFlow 当前支持的国内日线/实时适配 | 保留现有手 → 股、元不变、比例涨幅 → 百分数契约。第二次运行实时量额与此契约吻合；公开 API/SDK 字段说明未承诺所有市场统一单位，不能推广到其他市场或再乘一次 100。缺少量额仍为缺失。 |
| 腾讯实时 | 同一份 payload 的成交额÷候选股数与日内高低价优先交叉验证；兼容返回手或股，保留原有流通市值/换手率证据及传统兜底。35 字段金额为元；缺失时 37 字段万元 ×10000。14 位供应商时间按上海时区解析，未知不编造。 |
| 腾讯国内日线 | 保留既有规则：普通股票手 → 股，科创板 688/689 原值为股；缺少金额不按收盘价虚构。 |

真实运行反例（2026-10-16，亨通光电）：Efinance 原始成交量 1,023,074 手、成交额约 4,717,003,000 元，换算为 102,307,400 股。成交均价约 46.11 元，处于日内 45.20–47.00 元之间。旧展示“102.31 万股 / 47.17 亿元”隐含每股约 4610.62 元。昨日 1,121,314 手也必须转股，实时量与昨日量的比值约 0.91，不是 91 倍。此错误来自源单位漏转，不能通过改报告标签、改量比阈值或调整金额掩盖。

日线保存原有 upsert 会刷新重新获取日期的量额，无需数据库迁移；此次修复不直接改现有数据库或持仓。已保存的错误历史在对应日期重新抓取前不会自动修正，也不会靠价格比值猜单位。如已有当日日线，普通断点续传会跳过抓取，应通过现有分析 API 的 `force_refresh: true` 刷新所需窗口；没有缓存的 Actions 运行则正常抓取。未刷新的量价异常会明确披露并限制操作。

报价的 `stale_seconds` 始终保留报价至获取的真实秒差。有效性另按交易所日历判断：

- 当天 15:00 的完整 A 股报价在 15:12 获取，属于 `session_close`，不因超过 600 秒 TTL 判过期；756 秒仍照实记录，不改为 0。
- 必须是最近有效交易日的收盘时点（允许供应商一分钟内的时标差），且 OHLC、涨幅和量额字段完整、无量价矛盾，才能在盘后、周末、节假日或下一交易日盘前延续有效。下一交易日开盘后、错误交易日、陈旧盘中报价不能套用此豁免。午休仅认可该次午间收市时点的完整报价。
- 复用交易日历的实际收市时间，支持美国半日交易等边界。日历不可用不认证有效收盘；时间缺失/无时区/未来时标则明确未知。字段不完整的收盘报价为 `incomplete_close`，不认证为 fresh，也不混同为已确认价格过期。最新供应商报价仍不冒充交易所认证的最终日线。
- 交易日盘前/盘后、午休或休市日的供应商心跳时间，即使刚刚抓取，也不能单凭 age 较短认证常规交易报价；无法确认交易时段的近时报价为 `unknown_session`。近时盘中字段不完整则为 `incomplete_quote`。经核实的最近收盘/午休边界仍按上述规则有效。

数据检查统一用于行情元数据、模型上下文和最终报告：有限且合法的价格/量额、OHLC 区间、成交额÷股数与同一根 K 线高低价（保留 2% 上游舍入容差）、涨幅与昨收（允许价格分位舍入）、MA/RSI/MACD 的值域与样本情况。量价检查针对当前分析日线，不把早期复权价格与未复权成交额强行比较。只标异常，不自动把可疑数字乘/除 100。缺少昨收时标记 partial，不声称已完成涨幅关系核验；Efinance 只有实际涨跌额/最新价存在时才可计算昨收，不编造默认数值。仅消费收盘序列的 ETF 轮动仍可使用缺量额历史，缺失字段保持 NaN/None，不用于完整量价交易结论。

MA5/10/20 分别要求完整窗口；技术分析拒绝无效收盘/负量或非有限输入。`sample_count` 披露实际样本，RSI24 少于 25 根、MACD 少于 34 根等暖启动限制会标 partial；不改指标计算公式或按分数升级信号。异常/缺失检查进入 `market_data_validation` 和上下文块告警，两个报告渲染入口共用披露。缺乏完整依据时维持观望，不能将单位异常误解释为真实放量。

止损同时检查点位及风控/清单中的命名锚点（今日最低、MA5/10/20/60）。例如“43.00，跌破今日低点止损”与真实最低 45.20 不符时，原文、所报点位、引用锚点和触发文字保存在 `stop_loss_validation`；可执行止损字段标数据缺失，最终观望并提示核查，不擅自改为 45.20。经核对一致的条件止损和独立保护性点位保留。本规则不调整真实持仓或预设风控配置。

第三次运行的报告校验进一步覆盖全部股票和正文、嵌套计划与清单：

- **参考支撑**仅描述技术位置；**预警价**必须明确“仅观察、不自动卖出”；**实际止损触发价**是唯一可执行的保护条件。不同角色可以有不同价格，不能同时输出互相冲突的卖出触发。`risk_levels` 追加角色元数据，不更改既有字段。
- 原始报告完美世界为“9.45 元（跌破近期低点）”，风控另称“严格执行止损，若跌破 9.70 元短期支撑”。两者来自同一模型输出，不能推定 9.70 自动是预警价。校验保留原文和所有触发价供核查，隐藏冲突的可执行点位/指令、提示不可执行并观望；不替用户选取新的止损价。通用止损原则及与唯一点位一致的条件止损保留。
- 行情量比、当日量/昨日量、当日量/前 5 个完整交易日均量分别处理。报告量比字段以实际行情输入为准并附来源/报价时间；缺失、非有限或无效值显示 `N/A` 和“数据不足”，不输出 `None（缩量）`，不以模型猜测补值。日间比值可以保留为独立的数值事实，不能冒充行情量比或无口径的量能结论。技术量能计算需要当日及前 5 日的完整有效量，缺失状态为“数据不足”；零均量不能默认成缩量。
- 模型必须引用可核查字段、数值及比较口径。“洗盘”“抛压衰竭”等交易意图不能从量价单独证实；无可核查出处的确定判断改为明确的不确定性说明。成交量解读展示输入量比及来源，不用它证明交易意图；技术分析固定文案也不再断言“主力洗盘”。
- 最终操作、正文建议、止损、仓位和嵌套清单共同校验。观望不能附带建仓或数字仓位指令；正文中的独立买卖冲突也会触发保守处理。重复校验保留原始异常证据和校验记录，不反向升级信号。新字段仅作追加，API/Web 保持既有 dashboard 合同。

| 全市场成交额 | 上游统计缺失；个别指数成交额不代表统计范围相同的全市场成交额 | 保留缺失原因，不能未经口径核实直接相加上证综指和深证成指金额 |
| 止损 / 预警 / 目标 / 入场 | 原模型混合价格角色；旧守卫把错误说明放进价格字段；部分目标和“近期低点”没有真实锚点 | 五个价格字段保留为可空数字，诊断与原文单独保存；观察预警与止损分离。目标需匹配可核查均线；历史止损锚点未验证时不可执行；AI 条件计划不等于市场事实 |

| AI 遗漏 / 转换 / 重复提示 | 没有结构化数据的确定性渲染，依赖 AI 是否复述；两种渲染路径需同时覆盖 | 两种个股渲染均添加同一真实数据表；大盘注入实际新闻和统计。只去重重复列表提示，不删除分析项目或隐藏字段 |

### 采集与故障语义

`data_provider/cn_public.py` 使用已有 requests/pandas/BeautifulSoup 依赖；每个 HTTP
请求设置连接与读取超时，四个独立能力并行，各能力返回自己的状态、错误、来源、URL
和获取时间。成功数据短缓存保留首次获取时间，按日期及五分钟窗口隔离；失败不缓存。
它是原有来源之后的免费补充，并不保证第三方接口持续可用。资金接口失败不会尝试把
另一个行情接口中的同名字段 `f62` 当作资金净额，不同端点的字段编号不可互换。

财务金额仅在同一报告期补字段，新报告期替换时保留旧记录用于审计；历史事实、公司
公告目录、分析师预测与 AI 条件计划分别保存。公告日期只有日精度时不能确认具体发布
分钟；抓取时间始终单列。新闻要求精确时间且不能晚于本次采集时间。旧日期资金记录
保留真实交易日，不能写成“今日资金”。

本次免费在线验收是第四次运行之后的独立取数，**不是重写 18:22 的历史报告，也不是
声称这些数据在当时已被原任务取得**。不额外调用 AI 或发 PushPlus 通知，避免收费与
重复推送。接口在线实测和离线自动测试分开记录；自动测试的公开样本有采集说明，
不存在以虚构行情提高补齐率的情况。
